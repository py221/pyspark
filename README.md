# PySpark and Spark ML: a learning path

Worked examples and study notes that take you from RDDs to a saved, reusable Spark ML pipeline.
Everything runs locally in plain PySpark (local mode) on small synthetic datasets that a script generates,
so there is nothing to download and no cluster to set up.

```
 01 RDDs  ->  02 DataFrames  ->  03 Data lakes  ->  04 Streaming  ->  05 ML  ->  06 MLOps
 how Spark    tables, SQL,       messy files to     incremental       features,   missing values,
 thinks       windows, parquet   partitioned tables  queries           pipelines,  save/load,
                                                                      tuning      batch scoring
```

Each stage folder has a `notes.md` (concepts, gotchas, diagrams) and small scripts you can run and edit.
Read the notes first, then run the scripts and compare the printed output with what the notes say.

## The path

| stage | what it covers | key takeaways |
|---|---|---|
| [01-rdds](01-rdds/notes.md) | SparkContext, creating RDDs, transformations vs actions, lazy evaluation, pair RDDs, joins, `reduceByKey` vs `groupByKey` | Nothing runs until an action; combine before you shuffle; lineage is how Spark recovers |
| [02-dataframes](02-dataframes/notes.md) | schemas and CSV options, DataFrame API and SQL, joins, window functions, writing parquet | Explicit schemas beat inference; windows compute per-row values without collapsing rows; parquet keeps types and prunes columns |
| [03-data-lakes](03-data-lakes/notes.md) | regex parsing of web logs, timestamps, nested JSON and `explode`, partitioned tables and partition pruning | Parse defensively and count the failures; `explode` drops empty arrays; partition on low-cardinality columns and watch file counts |
| [04-structured-streaming](04-structured-streaming/notes.md) | file-source streams, event-time windows, watermarks, output modes, `foreachBatch` | A stream is an unbounded table; watermarks bound state; make batch writes idempotent |
| [05-machine-learning](05-machine-learning/notes.md) | feature engineering, `Pipeline`, train/test split, regression and classification, `CrossValidator`, `TrainValidationSplit` | Fit on train only; beat a baseline before celebrating; accuracy hides imbalance; keep grids small |
| [06-mlops](06-mlops/notes.md) | missing values, categorical encoding, scaling, saving and loading pipeline models, batch scoring | Put all preprocessing inside the pipeline; `handleInvalid="keep"` for scoring; check outputs, not just inputs |

## Layout

```
README.md
requirements.txt
common/spark.py            shared local SparkSession builder and path helpers
scripts/make_data.py       generates every dataset in data/ (fixed seed, stdlib only)
scripts/run_all.sh         generate data and run every stage script
data/                      small synthetic datasets (web logs, orders, nested events, houses, churn, stream files)
01-rdds/ ... 06-mlops/     notes.md + numbered example scripts per stage
tests/                     pytest smoke tests and a run-every-script test
output/                    created on first run, git-ignored (parquet, models, checkpoints)
```

## Setup

Requirements: Python 3.9+ (tested on 3.11) and a Java 8, 11 or 17 runtime (tested on 17); Spark runs on the JVM.

```bash
# make sure a JDK 17 is installed and JAVA_HOME points at it
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python scripts/make_data.py        # regenerate data/ (optional: it is already committed)
```

`pyspark` is pinned to 3.5.3. All scripts build their session with `common/spark.py`: `local[2]`, 4 shuffle
partitions, UTC time zone, no web UI, and everything written under `output/`.

## Running

Run any script from the repository root:

```bash
python 01-rdds/01_context_and_laziness.py
python 04-structured-streaming/02_windows_and_watermarks.py
python 06-mlops/03_save_load_pipeline.py
```

Or run them all, then the tests:

```bash
scripts/run_all.sh
pytest -q
```

Notes on the scripts
- Each one starts and stops its own SparkSession, so they can run in any order. Exceptions: `03-data-lakes/03`
  reuses the cleaned logs from `03-data-lakes/01` if present (and rebuilds them if not), and `06-mlops/04`
  trains a model itself if `03` has not saved one.
- Streaming scripts use `trigger(availableNow=True)`, so they process the sample files and exit.
- Spark prints a lot of log noise on first start; the scripts set the log level to `ERROR`.
- One script (`06-mlops/02`) deliberately triggers an unseen-label error, and Spark logs it before Python catches it.

## Datasets

All generated by `scripts/make_data.py` with a fixed seed, so every run produces the same files.

| file | shape | used for |
|---|---|---|
| `access_log.txt` | 2,005 web server log lines, 5 malformed | regex parsing, timestamps, partitioning |
| `orders.csv`, `customers.csv` | 1,200 orders, 150 customers (some orders reference unknown customers) | DataFrames, joins, windows |
| `sensor_readings.tsv` | 600 tab-separated lines, some broken | RDD cleaning, CSV options |
| `events.jsonl` | 500 nested events with arrays and an optional struct | JSON and `explode` |
| `stream_source/` | 5 JSON files of 60 events | streaming |
| `houses.csv` | 800 rows, numeric target `price`, a few nulls | regression |
| `churn.csv` | 1,500 rows, binary target `churned`, nulls | classification and MLOps |
